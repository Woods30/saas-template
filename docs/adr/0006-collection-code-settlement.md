# ADR-0006: 核销型支付——个人收款码 + 金额指纹 + 人工核验

- **状态**：Accepted（2026-11-05）
- **日期**：2026-11-05

## 背景

现有支付链路（ADR-0003 第 4、8 条）假定：provider 提供**托管结账页**、**价格目录**、
**webhook 自动核销**与 **Customer Portal**。要支持个人收款码（支付宝 / 微信），
这四样一个都没有，于是有两种走法：

**走服务商 API。** 官方规则允许个人支付宝账号签约电脑 / 手机网站支付，但线上额度
单笔 ≤ ¥50、单日 ≤ ¥1000（补个体工商户执照可解除），且要求**网站已 ICP 备案、备案主体
与支付宝账号主体一致**；周期扣款（商家扣款）仅企业账号，新版还要求注册资本 ≥ 2000 万
且近半年月活支付用户 ≥ 300，个人不可能通过。Stripe 与 Creem 的 Alipay 均为**一次性
付款、无自动续费**，且 Stripe 的商户主体国家白名单不含中国大陆。
来源：`https://opendocs.alipay.com/open/00dn7j`、`https://ideservice.alipay.com/cms/site/039qjw`、
`https://opendocs.alipay.com/open/0izsmy`、`https://docs.stripe.com/payments/alipay`、
`https://docs.creem.io/merchant-of-record/finance/payment-methods`。

**走个人收款码。** 个人经营收款码没有商户级 API，也没有到账通知；到账要靠人工核对
（依据：开放平台文档树中不存在「经营码」接口，且它只作为账单下载的签约产品出现，
置信度中高）。

第二条路不需要商户资质、不受个人主体线上额度约束、还能同时收微信与链上资产，
代价是**放弃自动对账**，改为「用户付款 → 申报 → 人工核验 → 才确认到账」。
本 ADR 记录选择第二条路及其全部约束。

## 决策

1. 新增一种与 provider 并列的结算形态：**核销型支付**（collection-code settlement）——
   用户按订单指定的金额自行付款，系统按金额匹配，**核验后**才确认到账。
2. 核销型支付**不实现 `PaymentProvider`**：它没有托管结账页、没有 webhook、没有
   Customer Portal，与 ADR-0003 的 provider 契约语义不符，硬塞会让接口同时表达两种语义。
   核验通过时**合成一个 provider 事件**交给通用 `payment/events.ts` 落库，复用幂等、
   付款记录、订阅位与通知。
3. **订单与付款记录分离**：新增 `collection_orders` 表承载业务意图（商品、应付金额、
   状态、有效期）；`payments` 表只记资金事实，**核验通过才写入**。待支付订单还没有钱，
   不能占用「资金事实」表。
4. **金额指纹**：应付金额 = 标价 + 尾数（分位）。同一收款账户下，待支付与待核验
   订单的**应付金额全局唯一**；订单有效期 **15 分钟**，过期后尾数释放；每个标价最多
   尝试 99 个尾数。按收款账户约束比按商品 + offer 更强，能防止不同商品价格区间重叠时撞单。
5. **核验方式**：管理员在管理台逐笔核对收款流水后确认。用户可上传付款凭证作辅助，
   但凭证**不作为放款依据**（可伪造）。核验接口按渠道抽象，为自动核验（链上交易查询）
   留位。
6. **待支付 / 待核验不占订阅位**：核验通过才占用账号唯一的订阅位；同商品重复下单
   先到先得，其余作废退款。
7. **没有自动续费**：订阅退化为「用户到期前自行下单 + 人工核验后续期」。页面必须明示
   「不自动扣款」。
8. **金额事实源回到本仓配置**：核销型渠道没有价格目录，金额与周期声明在
   `src/config/products.ts`。这是 ADR-0003 第 2 条「销售引用来自 provider」在该形态下的
   例外，不是第二份金额。
9. **交付仍然人工**：核验通过只写付款记录与订单状态；源码 / 访问方式由人工邮件发出
   （沿用现状，模板不实现履约）。
10. **风险告知落在页面正文**：结算页与商品页必须写明「人工核验，到账后 N 小时内开通」，
    不用弹窗。

## 后果

- 无商户号也能收款，能同时支持支付宝 / 微信 / 链上资产；但**无自动对账、无自动退款、
  无法自动开票**，到账与开通之间有人工延迟。
- 尾数池有限（同一基准价 99 个），并发订单多时需排队；用户改价、订单过期后才付款的
  款项**无主**，只能人工处理。
- 订阅没有自动续费，长期续费依赖用户主动下单；续费提醒是运营问题，不是技术问题。
- 个人收款码用于经营收款有平台规则与风控风险，属运营侧责任；模板负责把风险告知写进
  页面，不负责合规判断。
- ADR-0003 的「provider 托管 + webhook 自动核销」仍是默认路径；核销型是并列的第二条
  路径，不替代它。
