# 开发流程分层设计

日期：2026-10-15。
状态：对话设计已获用户批准；本文件记录实施规格。

## 1. 目标

降低日常开发循环的耗时，同时不牺牲核心代码的回归保障。核心策略：**默认只跑受影响的
测试；仅当改动命中核心区时才跑全量回归 + e2e。**

## 2. 当前源码事实（均已实测）

### 2.1 脚本与耗时

`package.json` 的 `check` = `locale:compile && biome check . && tsc --noEmit && check:env
&& locale:check`，5 步串行、全量。实测（本机 node v22.23.2、vitest 5.0.3）：

| 步骤 | 范围 | 冷 | 热 |
|---|---|---|---|
| `locale:compile` | `project.inlang` → `src/locale/paraglide` | **~18s** | ~1s |
| `biome check .` | 全仓 271 文件 | ~7s | 0.15s（有缓存） |
| `tsc --noEmit` | 全仓，无 incremental | ~15s | ~6s |
| `check:env` / `locale:check` | 单文件 | 各 ~2.8s | 各 ~2.8s |
| 全链 | | **~45s** | **6.9s** |

### 2.2 瓶颈点（按影响排序）

1. **`locale:compile` ~18s，且在 `check` / `typecheck` / `test` / `test:watch` /
   `check:locale` 里被重复调用**，无缓存复用。提交前跑 `pnpm check && pnpm test` 会编译
   两次 locale。
2. **`pnpm test` 只跑单元测试**（`tests/unit/**`，37 文件 / 602 用例，50–96s）；组件测试
   （`tests/components/**`，19 文件 / 160 用例）**不在其中**，须显式加
   `--config vitest.components.config.ts`。覆盖率也只覆盖单元。
3. **`vitest.workspace.ts` 是死配置**：引用三个 config 聚合成 workspace，但全仓无任何地方
   引用它，且 vitest 5 已废弃该文件（改用 `test.projects`）。
4. **CI 三 job 串行**（`lint-typecheck-test` → `build` → `e2e`），各自 `pnpm install` +
   `content:build`；`build` 在 job2 / job3 各跑一次；e2e 全量 49 用例在 `workers: 1` 下
   串行。无 paths 过滤 / affected 检测——改一行文案也跑全量 e2e。
5. **无任何 pre-commit hook**（无 `.husky/`、无 lefthook、`.git/hooks/` 只有 sample，
   `package.json` 无 lint-staged）。「提交前跑 check + test」仅靠 `CONTRIBUTING.md` 约定。
6. **无选择性运行机制**：无 `--changed` / `--related` / tags / projects 分组（除三个物理
   分目录的 config，且其中之一失效）。
7. **测试 flakiness**：默认 `testTimeout` 5000ms，全量并行下偶发超时（实测首次全量
   14 failed，重跑全绿），导致反复重跑。
8. **`.content-collections/generated/index.js` 每次构建变 `M`**：`@content-collections/core`
   把 `new Date()` 写进生成头注释。该目录在 `.gitignore` 第 5 行，但 6 个生成文件在
   `7257d80` 被 `git add -f` 强制纳入版本控制（AGENT.md 记为「git-ignored 但在版本控制中」
   是有意为之）。跑一次 `dev` / `build` / `content:build` 即产生噪音 diff。

## 3. 设计

### 3.1 消除重复的 `locale:compile`（对应瓶颈 1）

`locale:compile` 的产物（`src/locale/paraglide/**`）是生成物，只要 `messages/*.json` 与
`project.inlang` 未变即为最新。做法：

- 在脚本层引入**幂等编译**：`locale:compile` 先比对输入（`messages/*.json`、
  `project.inlang`、`project.inlang/**`）的 mtime 与产物 mtime，输入未变则跳过编译，直接
  退出。`check` / `typecheck` / `test` 继续调用它，但重复调用近乎零成本。
- 保持 `pnpm locale:compile` 命令名与语义不变（强制全量时可用 `--force`）。

**验证**：连续两次调用，第二次耗时 < 1s；改一个 `messages/*.json` 后编译重新执行。

### 3.2 测试分组接线（对应瓶颈 2、3）

- 删除失效的 `vitest.workspace.ts`，改用 vitest 5 的 `test.projects`（在
  `vitest.config.ts` 里声明 unit + components 两个 project），使 `pnpm test` **真正跑全部
  单元 + 组件测试**。
- workers 组当前 0 用例，保留其 config 与 `pnpm test:workers`，但不并入默认 projects
  （避免空跑开销）。
- 覆盖率门槛对 unit + components 合并计算。

**验证**：`pnpm test` 输出的用例数由 ~602 升至 ~762；`pnpm test` 能捕获组件测试的失败。

### 3.3 分层门禁（对应瓶颈 4、5、6）

**本地默认**：

- `pnpm check`（不含测试）+ **只跑受影响的**单元 / 组件测试。
- 受影响测试的判定用 vitest 的 `--changed`（基于 git）或 `--related <file>`。提供
  `pnpm test:affected` 脚本封装。
- 新增 pre-commit hook：仅对**暂存文件**跑 `biome check --write`（快，< 1s）。用
  `simple-git-hooks` + `lint-staged`（轻量、无 husky 的额外依赖面）或等价方案。

**全量回归 + e2e**：仅当改动命中**核心区**（见 3.4）。

**CI**：

- 保留 `lint-typecheck-test`（含全量测试）与 `build`。
- **e2e job 加触发条件**：仅在 (a) PR 命中核心区文件，或 (b) push 到 `main` 时运行；普通
  PR 跳过。用 `paths` 过滤 + 一个轻量的「改动是否触及核心区」判定步骤实现。
- 顺带消除 CI 重复：`pnpm install` / `content:build` 用缓存或 job 间 artifact 复用。

**验证**：改一个非核心文件（如 `src/components/blocks/marketing/hero/Hero.tsx`）的 PR
不触发 e2e；改 `src/auth/**` 的 PR 触发。

### 3.4 核心区清单（全量回归 + e2e 的判定依据）

命中以下任一即视为核心变更：

- `src/auth/**`
- `src/payment/**`
- `src/env/**`
- `src/lib/module-access.ts`、`src/lib/module-access.server.ts`
- `src/db/**`、`drizzle.config*.ts`、`src/db/migrations/**`
- `src/server.ts`、`wrangler.jsonc`
- `src/routes/api/**`
- `src/config/website.ts`（单一配置入口，影响面广）
- `src/lib/locale.ts`、`src/locale/middleware.ts`（locale 协商）

清单集中定义在一处（如 `scripts/core-paths.ts` 或 CI 的 paths 列表），供本地脚本与 CI
共用，避免两处维护分歧。

### 3.5 顺带修复（对应瓶颈 7、8）

- **超时**：在 vitest 配置里显式设 `testTimeout`（如 15000ms）与 `hookTimeout`，消除负载
  相关 flakiness。
- **`.content-collections` 噪音**：**去掉生成头的时间戳**（用户已确认此方案）。最小改动，
  保留「构建产物在版本控制中」的既有约定。做法：在 `content-collections.ts` 的构建后处理
  或 vite 插件里，把生成的 `index.js` 首行时间戳注释改为固定字符串（如
  `// generated by content-collections`）。若上游不提供钩子，则在 `content:build` 脚本后
  追加一步规范化。

**验证**：连跑两次 `pnpm content:build`，`git status` 不再出现 `M
.content-collections/generated/index.js`。

## 4. 全局约束

- 不新增依赖前先确认既有依赖无法满足；本设计可能引入 `simple-git-hooks` + `lint-staged`
  与 `@tailwindcss/typography`（后者属 Spec A），需在计划中单独列出并确认。
- 提交仅在全部测试通过、Linter 警告为零时执行；提交消息末尾附
  `Co-Authored-By: Claude Code <noreply@anthropic.com>`。
- 结构整理与行为修改分开提交。
- CI 与本地脚本共用同一份核心区清单，不得两处各写一份。

## 5. 提交切分

1. chore：删除死配置 `vitest.workspace.ts`，改用 `test.projects` 合并 unit + components。
2. perf：`locale:compile` 幂等化，消除重复编译。
3. chore：调高 vitest 超时；规范化 `.content-collections` 生成头。
4. feat：核心区清单 + `test:affected` 脚本 + pre-commit hook。
5. ci：e2e 改按核心区 / main 触发，消除重复 install / build。

## 6. 验证方式

- `pnpm test` 覆盖 unit + components 且全绿；连续两次 `pnpm check` 第二次显著更快。
- 非核心改动的 PR 不跑 e2e，核心改动跑。
- 两次 `content:build` 后 `git status` 干净。
- 全量回归在核心区改动下仍能捕获失败。

## 7. 非目标

- 不引入 turbo / nx 等增量构建系统（当前仓库规模不需要）。
- 不改变现有测试的组织方式（文件仍在 `tests/unit`、`tests/components`）。
- 不追求把 CI 压到极致的并行度，只消除重复与按需触发。
