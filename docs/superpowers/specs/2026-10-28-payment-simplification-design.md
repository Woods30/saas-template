# 支付与套餐配置精简设计

## 已确认的目标

模板使用者可以在 `src/config/products.ts` 配置多种套餐和价格，用户选择后购买。站点统一选择一个支付服务商；本次保留 Stripe 实现，为 Creem 等服务商提供可实现的适配边界，不实际接入新服务。一个账号全局最多一份有效订阅；独立一次性商品允许另外购买及重复购买。

不处理历史数据兼容、数据转换或服务商迁移；不操作生产资源，不清空本地数据库，不自动提交或推送。沿用 TanStack Start、React、Drizzle/D1、Paraglide 和现有依赖。所有改动遵循 AGENTS.md。

## 配置

每个套餐只声明一次：`id`、`name`、`description`、`features`、可选 `recommended`、`prices`。`prices` 是本站选项 ID 到当前服务商销售引用的映射，例如 `{ monthly: 'pro_monthly', yearly: 'pro_yearly' }`。Stripe 适配器把引用解释为 lookup_key，未来 Creem 可解释为 Product ID。金额、币种、类型和实际周期从服务商读取，不重复配置。

`getProducts()` 在调用时求值国际化文案，不能在模块顶层调用消息函数。空 prices 为免费套餐，按钮跳注册或工作台。付费按钮、周期标签、推荐标签统一生成。默认保留免费套餐和现有 Pro 月/年价格引用，新增套餐不要求同步其他清单；原 lifetime 保留为独立一次性商品示例，不再表示替代订阅或更高等级，避免现有 Stripe 价格引用无谓变更。Starter / Pro 是可配置能力，不要求创建线上 Starter 商品。

配置校验覆盖重复产品 ID、重复销售引用、空引用；价格目录失败明确禁购，不能伪装成注册流程。目录缓存按 provider 与引用集合隔离。

## 购买和管理

公开展示 Pricing。购买需要登录；登录后回 Pricing 恢复产品与选项，用户再次点击确认。客户端只提交 productId、offerId，由服务端解析真实价格。保留鉴权、模块门禁、限流和同源回跳检查。

active、trialing、past_due、unpaid、paused、incomplete 占订阅名额；canceled、incomplete_expired 不占。取消续费但周期尚未结束仍占名额。已有占位订阅时引导管理，不新开订阅。并发及尚未完成的 Checkout 必须通过持久化预留和服务商幂等避免重复创建，失败可安全重试；一次性购买不受订阅名额限制。

移除所有站内切换、升级差价、降级调度、pending 状态、等级互斥、买断接管及自动取消旧订阅。托管 Portal 处理取消续费、支付方式、发票，以及后台实际开放的切换能力。本站不修改后台设置，不保证所有 provider 有相同 Portal 能力。

## 服务商边界与 Webhook

PaymentProvider 暴露价格查询、Checkout、Portal、必要的订阅读取及验签解析。通用价格采用销售引用和外部价格/商品 ID，不能依赖 Stripe itemId、proration 或 Product 兜底规则。provider 各自把签名与原始事件解析为归一化事件/状态，通用持久化逻辑不读取 Stripe 原始 payload。

Webhook 是付款与订阅同步的权威入口，支付回跳只展示结果。保留验签、幂等和失败重投；业务交易唯一性与事件去重分别处理。订阅乱序不得恢复已终止状态或覆盖较新快照，必要时读 provider 最新状态。Portal 改套餐后按真实销售引用更新归属，不能让旧 metadata.productId 覆盖实际价格。一次性延迟支付未成功不能记成已付。退款保留退款金额，部分退款不能标为全额退款。

## 账单与数据

账单页展示有效订阅及状态、金额周期、续费/到期时间和管理入口；无有效订阅显示空态；保留简洁交易与历史。删除最高等级、接管、待切换和切换目标卡片。仅一次性购买用户也可根据已验证本地归属获取 Portal。

订阅和交易记录保留 provider、本站产品/选项、外部客户/订阅/付款标识及必要时间和金额字段。删除 pending 列和 Stripe Product 互斥专用字段。新增 Checkout 预留记录支持并发购买防重。使用新迁移表达 schema 调整，不编写历史数据转换，不应用生产迁移。外部 ID 唯一性使用 provider 作用域。

## 验收

按 TDD 调整目录、购买守卫、并发防重、客户归属、Webhook 验签/异步支付/重试/乱序/退款及账单测试；删除只验证旧能力的测试。更新中英文支付文档、配置说明、ADR 和术语中的过时约定。执行 pnpm check、unit/components、build、客户端 secret 检查及相关本地 E2E。真实服务商调用是否实测需如实报告，不以 mock/E2E seed 宣称真实扣款验证。

## 实现者决定

在现有目录内按职责拆分必要文件；不建立通用支付框架，不增加外部库。金额采用货币最小单位，按币种格式化。默认示例继续引用现有 Stripe 价格，避免未经授权创建远程商品。旧订阅和支付历史不转换，保留迁移文件历史，不清空数据库。
